# CSS architecture: scoped components + native custom elements for layout, no Shadow DOM

Doula Cloud's component library (atoms/molecules/organisms, per #93) styles itself with scoped Svelte `<style>` blocks reading design tokens (#94) as CSS custom properties — not a utility-first framework — since that's native to Svelte's build-time class-rewriting and needs no extra tooling. `@layer reset, tokens, base, utilities, components;` is declared once, project-wide, so specificity conflicts between the reset, tokens, page-layout utilities, and components resolve by explicit order rather than accident; verified by compiling a test component that wrapping `<style>` in `@layer components { ... }` still preserves Svelte's scoping class. Responsive behavior defaults to container queries (`@container`, `container-type: inline-size`) rather than viewport media queries — "intrinsic design" — reserving media queries for page-level/viewport-relative layout and `prefers-*` user settings; this is safe given the evergreen Chrome/Edge/Safari-only browser target (Firefox unsupported).

The one genuinely surprising piece: the page-level layout-primitive layer (Stack, Cluster, Sidebar, Switcher, Center, Grid, and the rest of Every Layout's 13 patterns — research in `docs/research/every-layout-css-primitives.md`) is implemented as our own **native Custom Elements**, not Svelte components, and explicitly **without Shadow DOM**. This looks like it fights the rest of the stack, so it's worth writing down why:

- **Rule of Least Power.** Every Layout's own author documents (in "Eschewing Shadow DOM," cited in the research doc) a pattern where a layout primitive's *default* configuration is a plain CSS rule — e.g. `center-l { margin-inline: auto; max-inline-size: 65ch; }` — needing zero JavaScript. A `get`/`set` attribute-reflection pair only runs JS to override the default when an instance sets a non-default value. That's the HTML-before-CSS-before-JS ordering this project wants, and it's a stronger fit than a Svelte component, which always ships a component instance's worth of JS whether or not any prop deviates from default.
- **No Shadow DOM, deliberately.** The same post documents specific, concrete Shadow DOM failures for this exact use case: universal (`*`) selectors pierce inconsistently (`color` crosses, `box-sizing` doesn't), `::slotted()` doesn't support sibling combinators (breaking Stack's adjacent-sibling technique), and instance styles lose specificity fights against document-stylesheet defaults without `!important`. Light DOM avoids all of it and keeps these elements stylable by the same `@layer utilities` and design tokens as everything else — consistent with how Svelte's own scoping (also not Shadow DOM) already works here.
- **Framework-agnostic reuse.** Because these are plain custom elements with no SvelteKit dependency, the same implementation could work unmodified in a future Hugo-based marketing site without a shared build pipeline. That's a reason to prefer this shape now, not a scope change: implementing anything in `hugo/` stays outside #93, which remains app-only.

Considered and rejected: using Every Layout's own shipped custom-element downloads (`<cluster-l>` etc., available under our paid license) directly, instead of reimplementing. Rejected on staleness risk — the site shows uneven updates across primitives (e.g. `gap` fully adopted on the Switcher page but not consistently elsewhere) — and because "informed by, not dependent on" keeps us able to fix or extend a primitive without waiting on a third party. Also considered: buying into Every Layout's Shadow-DOM-based custom-element packaging as-is, before finding the "Eschewing Shadow DOM" post — the post itself is the reason that path was dropped, not a preference decided in the abstract.

All 13 primitives are built in one foundation-wiring pass rather than sequenced against individual page needs, now that every primitive is fully sourced (free + unlocked via the paid license) and the marginal cost of the full set is low.
