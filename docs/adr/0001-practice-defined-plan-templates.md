# Practice-defined templates for Care Plan and Birth Plan

Care Plan and Birth Plan content varies a lot from practice to practice, and a fixed set of database columns would force every practice into the same shape. Instead, each Practice defines its own template (a set of fields, chosen from a fixed palette: short text, long text, single-select, multi-select, checkbox, section header) per plan type via a settings screen — no drag-and-drop builder for v1, just add/remove/reorder. Each filled-out Care Plan or Birth Plan instance stores a **snapshot** of the field definitions it was created against, not a live reference to the Practice's current template, so editing a template later never rewrites or breaks a Client's already-completed plan. New Practices get a seeded default template for both plan types.

In plain terms for the schema: this means Care Plan and Birth Plan data is **not** a fixed set of table columns. It's stored as flexible key-value/JSON content (both the template definition and each instance's answers), which is a deliberate departure from the plain-columns approach used elsewhere in the schema — don't "fix" this into fixed columns without re-reading this ADR.
